# 镜像信息页

案件与检材的基本操作见 [使用指南](USAGE.md)。iOS 本地备份的密码、异常检查及报告导出单列在 [iOS 备份](IOS_BACKUPS.md) 中。

镜像信息页是一页概览，不分页签。从上到下依次是：

1. **检材头部**：文件名与格式（VMDK、EWF 等代号，会话镜像写「解密视图」「VSS 卷影副本」），完整路径（可复制），逻辑大小；实际占用只在与逻辑大小不同时（压缩、稀疏格式）跟在后面。右侧是平台识别结论（平台 · 检材类型 · 厂商，备份另加徽章）和重新识别按钮；首次打开且没有结论、也没有进行中的识别时自动识别一次。页面只显示结论，逐分区判定与告警随回写存入案件。
2. **卷与分区**：标题行写分区表类型和分区数，右侧「解锁加密容器」以弹窗解锁 LUKS / VeraCrypt。下面是磁盘图（斜纹底为未分配空间，有未分配时在图下注明大小），点击色块滚动定位并高亮对应分区，悬停时色块与分区行同步。分区表每个分区一行：名称、文件系统、起始扇区、大小和操作。结束扇区、扇区数和字节偏移在起始扇区的悬停提示里。没有可浏览数据结构的分区（MSR 等未知类型、BIOS Boot、扩展分区）整行弱化。操作列按分区给出：
   - 挂载 / 共享（可挂载的文件系统；BitLocker 解锁后才出现）。
   - BitLocker 锁定状态、解锁和导出解密镜像。
   - LUKS 分区的「解锁」，打开解锁弹窗并预选该分区。
   - 卷影副本：有副本时显示「卷影副本 N」，点开在该行下列出副本（创建时间 UTC、属性、计算机名），可重建为只读镜像并在新标签页打开；有 VSS 区而无副本时显示「无卷影副本」（未创建，或已被删除）；VSS 元数据读不出时显示「卷影副本读取失败」，点开看原因。解锁 BitLocker 后重新读取卷影副本。

   归档、AD1、Docker 等逻辑证据没有分区表，这里只有一行合成根及其挂载入口。
3. **RAID 检测**：只在该镜像参与 LVM / mdadm 阵列、或可能是无分区表的阵列成员时出现。
4. **完整性校验**与**详细信息**并排（窄时上下排列）：
   - 完整性校验：算法开关与「计算哈希」在同一行；计算中显示进度和终止按钮；算完直接列出各算法的完整摘要。E01 带采集时记录的 MD5 / SHA1 时逐项标出一致、不一致或未校验，标题旁给出总体结论。读到坏区时提示哈希含合成零字节。
   - 详细信息：精确字节数、扇区大小、磁盘标识（GPT 磁盘 GUID 或 MBR 签名，可复制）；卷影副本会话另列来源分区、快照时间和卷影副本 ID。E01 的采集记录直接列出案件编号、证据编号、取证员、采集时间、设备型号和序列号，其余字段在「更多采集信息」中。镜像 ID 和镜像文件在本机的创建 / 修改时间不显示。

切换镜像后清除分区高亮、收起卷影副本列表与采集详情，并关闭解锁弹窗。窄窗口下分区表改为每个分区两行（名称 / 大小，文件系统、起始扇区 / 操作），表头收起，头部的平台结论移到大小下方。
