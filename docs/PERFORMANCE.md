# 性能验证

性能结论应基于当前提交的可复现场景。本文定义测量方法，不将旧行号、历史耗时或已修复问题作为当前缺陷清单。

## 测量记录

记录提交号、操作系统、CPU / 内存、存储介质、构建 profile、特性组合、镜像格式和逻辑大小。对文件系统操作另记录目录项规模、文件大小分布和卷类型；私有检材只记录可公开的规模描述。

分别测量冷启动和缓存命中，报告重复次数与耗时分布。同时观察吞吐、峰值内存、临时磁盘占用、读取次数、取消延迟及交互延迟。只比较结果字节、记录数和来源一致的实现。

## 代表场景

| 场景 | 观察目标 |
| --- | --- |
| 顺序整盘哈希与 RAW 导出 | 完整长度、吞吐、缓冲复用、坏区反馈 |
| 大目录和百万条 filedb | 首屏、翻页、排序、过滤、计数与内存 |
| 多卷快照与索引导入 | 构建时间、事务等待、取消、旧索引可读性 |
| 全局搜索 | 编码和正则匹配、分段结果一致性、命中落库、交互响应 |
| 文件雕刻 | 单 / 多线程结果一致性、解析读取量、暂停与取消 |
| 预览与并发操作 | 媒体缓存预算、引用释放、哈希期间目录浏览 |
| Dokan 实际挂载读取 | 随机寻址、每句柄窗口命中、短读错误与只读保护 |
| 插件分析 | 多任务调度、进度写入、结果上限与源路径读取 |
| 关闭案件与卸载镜像 | 任务退出、句柄释放和临时文件清理 |

## 基准入口

```text
just bench-filedb-store
just run-example-fast probe_partitions <image-path>
just run-example probe_carve <image-path>
```

更多示例参数从 `src-tauri/examples/` 中对应程序的帮助或源码确认。具体配方通过 `just --show <recipe>` 查看。

Dokan 性能比较需在 Windows 桌面实际挂载后测量，同时核验读回哈希、随机读取、只读保护和卸载清理。

桌面 `release` 采用体积优先优化，`release-fast` 用于性能比较。调优热点依赖时同时比较两者；完整 QR/OCR 构建与轻量构建的耗时不可直接混作同一基线。

## 回归要求

优化前后核验结果、长度和校验值。分页需要稳定顺序；并行扫描需要稳定合并；缓存需要有界容量和明确清理点。增加并发时，同时测量目录浏览等前台交互，避免只提高后台吞吐。

失败、取消、短读和 SQLite 忙等待也属于性能验证。测试与构建统一通过 [开发文档](DEVELOPMENT.md) 中的 `just` 配方。
